# 四维围棋 · 4D Go

一个免安装第三方依赖的 Python 小游戏。棋盘是四维格点，围棋的连接、气和包围规则沿四条坐标轴拓展；网页里的小棋盘是同一张四维棋盘的切片。

## 运行

需要 **Python 3.10 或更新版本**和现代浏览器。在本目录执行：

```sh
python3 app.py
```

Windows 可用 `py -3 app.py`，或 `python app.py`。macOS 可以双击 `开始游戏.command`；首次启动若系统拦截脚本，用上面的终端命令即可。程序自动选择空闲端口并打开浏览器；也可手动打开终端打印的 `http://127.0.0.1:端口`。

```sh
python3 app.py --no-browser --port 8765
```

在终端按 Ctrl+C 关闭服务。棋局保存在内存中，关闭前用界面的“保存”下载 JSON，下次启动后“载入”恢复。启动脚本和 Python 命令须在可写入下载文件的正常桌面浏览器中使用。

## 怎么理解四维棋盘

- 坐标为 `(x, y, z, w)`，全部从 0 开始。默认每轴 3 点，共 **3⁴ = 81** 个落子点；可切换 **4⁴ = 256** 和 **5⁴ = 625** 点。
- 默认一张切片显示 x/y，切片列改变 z，切片行改变 w。左右/上下的小棋盘通过同一 x/y 位置相邻，属于同一个棋盘。
- 只沿单一轴加减 1 为相邻；不算对角线、不首尾循环。内部点最多 **8 个邻点**，四维角点只有 **4 个邻点**。
- 同色棋子经任意轴相连组成一个棋块。气是这整个棋块接触的**不同空点**，同一个空点不能重复计算。

把鼠标移到棋点，或用 Tab 聚焦，会同时显示跨切片邻点、棋块与所有气。可交换显示轴来检查四维连接。点击落子，Enter/空格也可落子；方向键沿切片内坐标移动焦点。

建议先点“教学局面”：中心白子已被黑棋围住 7 个邻点，但仍有 `(1,1,1,2)` 这一气。在该点落黑，白子才被提走。它看起来在二维切片中早已被围住，却一直沿第四维连通。

## 本游戏采用的规则

1. 黑先白后。落子后先提取所有无气的敌方棋块，再检测己方气，禁止自杀。
2. **位置超级劫**：落子不能重现本局历史上已有的棋盘，不只禁止立即打劫。停着不受此限制。悔棋同时撤销对应历史限制。
3. 双方连续停着进入数子。面积分 = 活子 + 边界只接触本方棋子的空连通区域；边界接触双方或无棋子边界的区域为公气。
4. 数子时点击棋子，以整块为单位标记/取消死子；先移除全部标记死子，再按同一四维连通图重算。提子数供观察，**不会额外加入面积分**。死子判断由玩家确认；有分歧可以“继续对局”。
5. 白默认贴 **0.5**，新局可调整为 −50 到 50。四维棋盘没有采用这里经过验证的公平贴目；这是可调小游戏参数。

开局仅出现一种颜色时，预估面积可能把很大的空区都算给该方，因此它是**当前局面的预估值**，不代表最终胜负或棋力判断。终局死活确认后再看比分。

## 功能与限制

支持本地双人、电脑执白、启发式提示、停着、认输、悔棋、JSON 存取、死子确认与轴交换。电脑模式悔棋通常撤销人机各一手，返回黑方回合。

电脑会考虑提子、救急、连接与气，并避免明显填己方眼；它是入门启发式对手，不使用神经网络搜索，不自动判定死活。四维空间气多、包围难，优先体验教学局面与 3⁴ 小盘。

服务仅监听本机 `127.0.0.1`，没有远程多人、账号、上传或联网模型。同一个服务上的多个标签页共享一个棋局；旧页面操作会因版本冲突被拒绝并刷新，不覆盖较新棋局。刷新保留棋局，重新启动需载入存档。存档最多 3000 次行棋/阶段操作，HTTP 上传最大 2 MB。

## 验证与交付

```sh
python3 -m unittest discover -s tests -v
python3 build.py
```

测试覆盖真实规则引擎和实际本地 HTTP 请求，包括跨维提子、劫、自杀、计分、存档重放、版本冲突及电脑回复。`build.py` 仅用标准库生成 `artifacts/go4d.zip`，内含源码、界面、说明与测试。

`engine.py` 管规则；`ai.py` 管启发式选点；`app.py` 管本地服务；`static/` 管可视化。规则设计及验收标准见 `docs/design.md`。
